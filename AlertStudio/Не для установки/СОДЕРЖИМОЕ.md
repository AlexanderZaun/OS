# Что входит в программу

[Русский](<СОДЕРЖИМОЕ.md>) · [English](<CONTENTS.en.md>)

В родительской папке AlertStudio теперь два раздела:

| Папка | Содержимое | Для другого пользователя |
|---|---|---|
| Для установки | Готовая папка AlertStudio-&lt;версия&gt;-Windows-x64, ZIP и SHA-256 | Скачивается ZIP из GitHub Releases; распакованная папка работает самостоятельно |
| Не для установки | Всё, что нужно для разработки и проверки, но не для запуска готового приложения | Не входит в рабочий ZIP |

## Что находится здесь, в «Не для установки»

В «Для установки/Чистая сборка» находится новый чистый архив с отдельными инструкциями RU/EN. Рабочая папка программы с личной Data остаётся на прежнем месте.

- `adapters`, `app`, `contracts`, `core`, `locales`, `modules`, `sdk`, `ui-kit`, `index.html` — исходники. Сборщик создаёт из них файлы готовой программы.
- `tools`, `package.json`, `pnpm-lock.yaml`, `pnpm-workspace.yaml`, `tsconfig.json`, `.gitattributes`, `AGENTS.md` — инструменты и правила разработки.
- `node_modules` — установленные зависимости разработчика.
- `dist` — промежуточные результаты сборки и отдельно собираемые примеры расширений.
- `tests`, `.test-data`, `artifacts` — тесты, тестовые проекты, отчёты и снимки экрана.
- `docs`, `README.md`, `examples`, `reference`, `output` — документы, PDF сравнения, примеры и референсы.
- `tmp` — временные файлы.
- `Launch.exe`, `Launch.cmd`, `Launch.ps1` — запуск рабочей версии для разработки. Пользователь запускает AlertStudio.exe в «Для установки».

«Не для установки» **не означает «никогда не отправляется в GitHub»**: исходники, тесты и документация нужны в Git-репозитории для дальнейшей разработки. Локальные зависимости, временные файлы и результаты проверок игнорируются Git. Ни исходники, ни эти локальные материалы не входят в установочный ZIP из Releases.

Готовая программа создаёт свою Data внутри переносимой папки при первом запуске. Это личные настройки, проекты, расширения и черновики конкретного пользователя. Для переноса вашей установленной программы Data нужно брать вместе с ней; в чистый архив для других людей Data не включается. Не переносите личную Data в эту папку разработки ради обновления.

Команды pnpm выполняются отсюда. `pnpm package:portable` создаёт чистую сборку в соседней «Для установки», сохраняя это разделение при будущих сборках. Упаковщик останавливается, если прежняя готовая папка содержит Data или изменённые файлы. GitHub Releases получает только ZIP и SHA-256. Корневой скрытый .gitignore — служебное правило Git, а не часть программы.
