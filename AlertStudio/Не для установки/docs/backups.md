# История, бэкапы и GitHub

[Русский](<backups.md>) · [English](<en/backups.md>) · [Оглавление](<README.md>)

Различайте четыре механизма: история действий — до 100 сеансовых undo; project.previous.json — проверенный индекс прежней файловой ревизии; Recovery — отдельный черновик; Git backup tag — контрольная версия исходников. Они не заменяют резервное копирование личной Data.

main хранит опубликованные исходники. Версия v0.2.1 объединяет переносимую программу, новую структуру папок, двуязычную документацию и публичную витрину. Её контрольная метка — backup/2026-10-18-presentation-v0.2.1. Предыдущий v0.2.0/9dc7d2d сохраняется отдельно. Готовая программа скачивается из [Releases](https://github.com/AlexanderZaun/OS/releases/latest), а не из source ZIP.

Контрольные метки: backup/2026-10-17-before-application-menu (89320d4), backup/2026-10-17-application-menu (46e54bf), backup/2026-10-18-portable-v0.2.0 (9dc7d2d). Это исходники, не готовая установка. Tags → Code/Download ZIP нужной метки требует developer build; старые checkout-пути могут отличаться.

При каждой разрешённой публикации создавайте аннотированный backup tag нового коммита; прежний remote tip тоже сохраните, если подходящей метки нет. Имена уникальны, дата Europe/Minsk, повторный выпуск — с суффиксом/временем. Опубликованные tags не передвигать/удалять, историю не переписывать. Branch и явно указанные новые tags отправляются atomic push, затем сверяются remote SHAs. Это не разрешение на автоматическую публикацию.

Личные проекты, бэкапы, настройки и Recovery не включаются в установочный ZIP. Для своих данных копируйте Data при закрытом приложении и отдельно внешние project folders.
