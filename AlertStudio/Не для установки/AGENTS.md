# Инструкции разработки AlertStudio

[Русский](<AGENTS.md>) · [English](<AGENTS.en.md>)

## Область и структура

Работайте только внутри родительской AlertStudio. Исходники и инструменты находятся здесь, в «Не для установки»; готовая программа/ZIP/SHA — в соседней «Для установки». Используйте tools/distribution-paths.mjs, не фиксированные буквы дисков. Не переносите материалы разработки в runnable tree. Сохраните ../../smoke-configured.html и ../../prompt-ru.md. Корневой .gitignore исключает «Для установки»; исходники здесь публикуются отдельно.

## Архитектура и данные

Исключение для авторизованного оформления GitHub: публичные README.md/README.en.md в корне репозитория представляют программу пользователю. Поддерживайте их вместе с presentation и docs/github-presentation.md; остальные внешние файлы не перемещайте и не удаляйте. Страница приложения публикуется отдельно через GitHub Pages; дерево исходников на Code остаётся доступным.

- Core, contracts и sdk/index.ts независимы от React/Electron/Dockview/Canvas/Pixi/FFmpeg. Framework-код — в adapters/bootstrap или явно специализированных UI-контрактах.
- Определения настроек и сохранённые значения — отдельные файлы. Не заменяйте folder project одним JSON.
- Recovery находится вне явной папки проекта. Не называйте autosave явным Save. Сохраняйте Windows folder lease на весь сеанс; не заменяйте её удалением stale lock-файлов. Проверяйте полное резервное дерево перед fallback.
- Runtime extensions собираются отдельно, устанавливаются через staging и повторно проверяются перед активацией. Проект не исполняет код.
- SDK 0.1 экспериментальный; версии схемы, поведения и проекта независимы. Не объявляйте планы или непроверенное поведение работающими.

## UI, языки и проверки

Все платформенные подписи имеют RU/EN. Новые controls/panels используют ui-kit/theme.css; диалоги — ui-kit/Dialog.tsx, без отдельной палитры. Следуйте docs/design-system.md. При UI-изменениях осматривайте 900×650 и 1920×1080.

Для соответствующих изменений выполняйте pnpm typecheck, pnpm check:boundaries, pnpm test, pnpm build и pnpm test:ui. UI-проверки требуют Windows desktop. Для portable-изменений добавьте pnpm package:portable и pnpm test:portable. Для документации выполните pnpm check:docs; сохраняйте содержательное соответствие RU/EN, рабочие ссылки и актуальные статусы. Русские docs — docs/, английские — docs/en/; корневые пары README.md/README.en.md, AGENTS.md/AGENTS.en.md, СОДЕРЖИМОЕ.md/CONTENTS.en.md. Запускайте команды из этой папки.

## Готовая программа в GitHub

При разрешённой публикации отправляйте текущие исходники И проверенный самодостаточный Windows portable ZIP с SHA-256 в Releases. Source ZIP или backup tag не заменяет программу. Порядок: docs/portable.md, package:portable, test:portable, commit, аннотированные version/backup tags, явный atomic push, затем tools/github-release.mjs. Для нового выпуска выбирайте ещё не опубликованную версию.

Не включайте node_modules, Data, черновики, проектные бэкапы, логи, тесты, artifacts или референсы в runnable ZIP. Сохраните лицензии и обе пользовательские инструкции RU/EN. Packaged storage следует за EXE в Data независимо от cwd, developer profile и диска. Не перезаписывайте Release или папку с пользовательскими данными.

## Контрольные версии — требование пользователя

При каждой разрешённой публикации создавайте отдельный аннотированный backup tag публикуемого коммита. До обновления ветки сохраните её прежнюю удалённую вершину, если backup tag ещё не указывает на неё. Используйте уникальные backup/дата-описание с датой Europe/Minsk; для нескольких выпусков за день добавляйте время/суффикс.

Нельзя перемещать/перезаписывать/удалять опубликованные backup refs или переписывать историю ради их замены. Отправляйте branch и явно названные новые tags по возможности атомарно; проверяйте удалённые commit targets. Сообщайте коммит и backup tags пользователю. Это правило не разрешает незапрошенный push или автоматизацию. См. docs/backups.md.
