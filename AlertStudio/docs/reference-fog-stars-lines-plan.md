# План: туман, звёзды и сеть между звёздами

Это подробный план изменений, **не описание уже реализованных возможностей**. Срез исходников: 16 октября 2026 года, после коммита 5691d19. Цель — средствами AlertStudio собрать композицию и согласованное движение, похожие на вьюпорт smoke-configured.html, сохранив собственную архитектуру и независимые объекты.

Обновление: [первый связанный вариант реализован](linked-scene.md): cloud/rim fog, привязка stars к одному fog, отдельные ядро/halo, network, reordered layers, единый runtime clock и кнопка сцены-примера. Ниже сохранён исходный подробный план; перечисленные в нём расширения не следует автоматически считать выполненными.

Общий каталог остаётся в [10 блоках](feature-catalog-ru.md). Этот рабочий участок объединяет части блоков 1, 4, 6, 7 и 9. Молнии, гличи, звук, монтаж и экспорт не являются зависимостями этой задачи.

## 1. Целевая композиция и границы сравнения

В примере: сцена 1920×1080; область облака 900×480 в центре; четыре слоя тумана с разными оттенками и движением; 1900 мелких и 70 крупных звёзд; звёзды преимущественно вокруг облака, часть в центре; сеть из соседних крупных звёзд. Стиль сети — triangles, ограничение длины 180 scene px, толщина 0.7, цвет #42dfff. Эти значения — стартовый визуальный ориентир, а не готовый пресет для нынешних алгоритмов.

В референсе также есть отдельные flow/flying particles и Edge Light с нитями/искрами по границе. Они добавляют заметные детали на исходном снимке. Приёмку трёх выбранных систем сначала проводить на reference-кадрах с отключёнными посторонними слоями. В полном оригинале нельзя считать любые световые нити частью сети между звёздами.

Нужны два набора неизменных условий: исходные reference baseline и отдельный focused baseline для fog/small/large/lines на t=0/6/12. Оригинальный HTML не менять: тестовая конфигурация задаётся в запущенном экземпляре. Проверять также видео движения, чёрный/светлый/прозрачный фон и масштаб 100%. Побайтовое совпадение с чужой симуляцией не является целью.

## 2. Что уже работает и сохраняется

Произвольное число UUID-слоёв fog/stars, независимые настройки и копии, прозрачный Canvas2D, seeded генерация, аналитический seek, pause/resume, выбор/drag, zoom/pan/fit, общая история, отдельные окна, многофайловые проекты и recovery. 5000 звёзд на объект достаточно для целевых 1900 + 70. Не требуется увеличивать лимит ради этого примера.

Текущий fog: 36 клубов, texture 96×96, поверхность/маска 384×384, ellipse/rounded, один цвет, мягкость края и круглый центральный просвет. Текущие stars: независимое прямоугольное поле или четыре скопления, точки/четырёхлучевая форма, один параметр glow и дрейф с оборачиванием по краям. Готового модуля сети нет.

## 3. Общая основа: источники данных и время

Сейчас Effect.evaluate получает только values/time, а CanvasPanel независимо оценивает видимые объекты. Для зависимых эффектов этого недостаточно. Ввести контекст вычисления сцены с доступом к типизированным выходам выбранных UUID.

Предлагаемые связи: fog objects → small stars / large stars → network. Fog публикует общую геометрию, устойчивые идентификаторы/положения клубов и данные для выборки плотности. Stars публикует стабильные ID, мировые координаты, группу center/rim, размер, яркость и состояние участия в сети. Network ссылается на конкретный stars UUID.

Связи сохраняются по UUID, не по имени/позиции в Layers. Для них нужны декларации допустимых входов, редактор выбора источника и отдельные сохранённые ссылки; примитивные setting values не следует заменять произвольным вложенным JSON. Конкретное расширение contracts/SDK и формат файлов зафиксировать до кода, предусмотреть загрузку старых проектов, неизвестных ссылок и версии поведения эффектов.

Порядок вычисления зависимостей отделить от порядка рисования. На одном кадре каждый источник вычисляется один раз, даже если его используют два stars и сеть. Скрытые визуально звёзды могут оставаться источником сети; отключённый источник и отсутствующий UUID должны иметь отдельное понятное поведение. Циклы, несовместимые типы и отсутствующие зависимости диагностируются, чужие объекты не подставляются молча.

Один preview clock для сцены/окон: play, pause, seek, speed, duration, loop. Все зависимости получают одно и то же время. Проигрывание и выбор источника в preview не создают history/dirty; изменение сохранённой связи — обычная отменяемая правка проекта. Это базовое время сцены, не требование сразу реализовать полный монтаж/редактор ключей.

## 4. Туман: что переделать

### Геометрия облака

Добавить неровную форму cloud и вытянутую мягкую форму; управляющие параметры — ширина/высота, положение, поворот, масштаб неровностей, выраженность выступов, seed. Несколько fog должны уметь пользоваться одной областью облака и сохранять разные внутренние движения. Маска, распределение звёзд и координаты источников используют одинаковые преобразования scene/local.

### Структура и заполнение

Добавить распределение клубов «по области / по краю / смешанное», количество/разброс размеров, раздельный масштаб крупной структуры и мелкого шума. Внутри нужны мягкие неоднородные объёмы, на краю — более плотные участки. Сейчас случайное заполнение и радиальное вычитание могут давать отдельные пятна и чрезмерно круглый просвет.

Просвет в центре сделать управляемым по ширине, высоте, силе и мягкости, с небольшим смещением; форма просвета не обязана повторять внешний контур. Это позволяет оставить место под текст без жёсткого выреза.

### Цвет и прозрачность

Разделить цвет, яркость, плотность материала и opacity всего слоя. Для первого похожего варианта достаточно четырёх самостоятельных цветов с разной яркостью; сложный цветовой редактор не обязателен. Плотность не должна неожиданно отключать opacity. Уточнить определение каждого параметра, чтобы его влияние было предсказуемо при наложении слоёв.

### Движение

Добавить независимые по слою фазу, амплитуду, скорость и режим: медленное смещение, подъём/опускание, вращение вокруг области, дыхание/локальные завихрения. Нужны положения клубов в базовом состоянии и на текущем времени для привязки звёзд. Сначала сохранять аналитическую перемотку, не вводить stateful simulation без необходимости.

### Качество и стоимость

384×384 при растягивании на большое облако ограничивает детали. Добавить ограниченный режим качества поверхности/текстуры, учитывающий размеры области; например, черновой/обычный/высокий — точные размеры выбрать по измерениям. Отдельная мягкость края и внутренней структуры. Учитывать padding за границей для blur/glow, чтобы не обрезать ореол.

Не делать полный scene readback для каждого слоя. Геометрию/шум/плотность, нужные зависимым эффектам, получать из общей нейтральной модели; локальное чтение Canvas оставлять осознанной backend-операцией. Ограничивать поверхности и кеш, освобождать при смене качества/удалении.

Критерий: четыре fog образуют согласованное неровное облако с мягкой границей и свободным центром; изменение маски и движения согласовано со звёздами; seek повторяем.

## 5. Звёзды: что переделать

### Внешний вид

Добавить явно выбираемые square/circle/diamond/spark/star; для первого сравнения обязательна квадратная форма. Раздельные параметры ядра и ореола: размер, цвет, opacity, радиус/сила glow, использование цвета ядра. Белый центр должен отключаться — сейчас renderer добавляет его всегда. Размер ореола отвязать от размера звезды. Два пресета «мелкие / крупные» применяются к обычным независимым stars объектам.

### Распределение

Добавить режимы «внутри облака / по краю / смешанный», отдельное число центральных звёзд, ширину пограничной полосы, равномерность вдоль контура, число/силу сгущений и выход за границу. Привязать распределение к геометрии источника fog, а не к отдельной прямоугольной рамке. Сначала достаточно одного fog-источника с общей формой; несколько источников добавить с явным правилом смешивания.

### Движение и привязка

Сохранять стабильный ID каждой звезды и начальные случайные параметры. Добавить ограниченное плавное блуждание, амплитуду/скорость и независимую фазу. Для каждого элемента выбрать устойчивый anchor клубка/контура, хранить его локальное смещение и смешивать собственное движение с движением источника по attachment strength. Не переопределять ближайшую цель хаотически каждый кадр.

Текущий дрейф с wrap оставить отдельным режимом фонового поля. Для облачной композиции он не должен переносить звёзды с одного прямоугольного края на противоположный. При изменении seed/геометрии правила перестройки anchors должны быть определены.

### Мерцание, блики и следы

Добавить долю мерцающих звёзд, диапазон частот, глубину и профиль вспышки. Подмножество определяется seed, а не выбирается заново на кадре. Для крупных звёзд — короткие перекрёстные блики и слабый след. Сначала след вычислять по положениям звезды на t и t−Δt, чтобы прямой seek не требовал прогрева истории.

Не требуются для первого результата падающие звёзды, полноценные шлейфы или реакция на звук. Сохранить sprite cache, но расширить ключи на форму/ядро/ореол; ограничить число вариантов размеров и расход памяти.

Критерий: small/large визуально различимы, повторяют область и движение облака, при настройке собственных параметров остаются независимыми; их выходные координаты совпадают с центрами рисуемых звёзд.

## 6. Сеть между звёздами: что сделать с нуля

Создать отдельный эффект network с источником stars UUID. Стартовый источник — поле крупных звёзд. Вычислять сеть по готовым координатам источника, а не генерировать вторую копию звёзд с тем же seed. Скрытие ядер по выбору пользователя не должно автоматически уничтожать данные источника.

Первый набор настроек: источник, участие центральных звёзд, max distance в scene px, число соседей, режим «цепочки / треугольники / сеть / четырёхугольные связи», толщина, цвет, opacity, brightness, мягкое свечение. Четырёхугольные связи не обещают идеальную форму ромба при произвольных точках.

Для треугольников: выбирать ближайших допустимых соседей, соединять центр с ними, замыкать третье ребро только если оно также проходит ограничение расстояния. Исключить пары звезды с собой, дубликаты неориентированных рёбер и вырожденные группы. Порядок при равном расстоянии стабилизировать ID.

Чтобы сеть не мигала при прохождении порога, сначала использовать плавную прозрачность по расстоянию и детерминированные веса связей. При необходимости history-based hysteresis добавить только с правилами reset/replay/checkpoints. Не выбирать новых случайных соседей на каждом кадре. Отдельный параметр определяет, следует ли яркость линии мерцанию звёзд.

После базовой сети — dash/dot, пульсация, outline, тёмная поддерживающая обводка и отдельный радиус glow. Элементы должны использовать scene units и одинаковый transform с источником, включая поворот; zoom камеры не меняет толщину в данных сцены. Список рёбер не зависит от порядка рисования слоёв.

Для 70 крупных звёзд простой поиск соседей приемлем как исходный прототип. Для тысяч точек нужен spatial grid или иной локальный поиск, ограничения рёбер/соседей и предупреждение о нагрузке. Не строить все пары для 1900 мелких звёзд по умолчанию.

Критерий: концы всех рёбер совпадают с текущими центрами звёзд, сеть движется без отставания, нет дубликатов/непредсказуемых скачков; скрытые/удалённые/неизвестные источники обрабатываются явно.

## 7. Редактор и совместимость

Нужен reorder слоёв с undo, выбор источников в Properties с именем/типом/статусом, переход к источнику, solo и диагностика missing/cycle. Все контролы — RU/EN и общая тема. Не добавлять имитационные настройки без реализации.

Порядок по примеру: туман ниже сети/звёзд, мелкие и крупные звёзды независимы; фактический стек зависит от выбранной композиции. Для первого результата хватает source-over. Новые режимы blend вводить после конкретного сравнения; не объявлять GPU или сложный compositor обязательными заранее.

Старые fog/stars проекты должны открываться с прежним внешним видом либо через явную миграцию/новую версию поведения. Старый stars без source остаётся самостоятельным полем. Копирование связанных объектов требует определённого правила: дублировать ссылки на существующие источники или клонировать связанную группу с переназначением UUID. Удаление источника не удаляет потребителей и их настройки.

## 8. Порядок работ и приёмка

| Этап | Результат | Проверка |
|---|---|---|
| 0 | Focused reference baseline и тестовая сцена | Только fog/small/large/lines, фиксированные условия/время/seed |
| 1 | Общая форма/координаты облака и новые настройки fog | Мягкая неровная область, четыре слоя, качество и alpha |
| 2 | Typed source outputs, ссылки UUID и общий clock | Источники вычисляются один раз; render order независим; missing/cycle/hidden source |
| 3 | Формы/ядро/halo stars и распределение/attachment | 1900 small + 70 large; preview совпадает с выходными координатами |
| 4 | Network с triangles/nearest/distance | Совпадение endpoints, отсутствие дублей, seek 0/6/12 и обратный |
| 5 | Reorder, источники в UI, пресет композиции | Сцена собирается через интерфейс без ручного редактирования файлов |
| 6 | Сравнение, производительность, сохранение | Свой baseline, два размера окна, save/open, undo/redo, copy/delete source и disposal |

На каждом этапе обновлять definitions отдельно от saved values, tests и статус в основном плане. Измерять отдельно evaluate, поиск соседей, draw и расход кеша; дополнительно кадр всей сцены на целевом компьютере. Не выводить FPS студии из одного синхронного microbenchmark. Пример использует Canvas2D, поэтому начинать можно на нынешнем backend; GPU рассматривать по измерениям.

Результат этого участка — воспроизводимая связанная композиция из трёх систем. Светящиеся нити Edge Light, flow/flying particles, оформление текста и Dark Base остаются отдельными задачами, если целью позже станет полный исходный viewport.
