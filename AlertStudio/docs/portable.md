# Переносимая версия и публикация

## Для пользователя

Готовая программа для Windows 10/11 x64 находится в [GitHub Releases](https://github.com/AlexanderZaun/OS/releases/latest). Скачайте `AlertStudio-0.2.0-Windows-x64.zip`, полностью распакуйте в доступную для записи папку и запустите `AlertStudio.exe`. Установка Node.js, pnpm и настройка путей не нужны. Редактор работает офлайн. `Code → Download ZIP` скачивает исходники для разработки, а не готовую программу.

При первом запуске рядом с EXE автоматически создаётся `Data`:

| Папка | Назначение |
|---|---|
| Profile | Раскладки, распределение объектов и данные Chromium |
| Projects | Новые проекты при первом «Сохранить» |
| Recovery | Черновики восстановления вне папок проектов |
| Extensions | Установленные доверенные пакеты расширений |
| Logs, CrashDumps | Диагностика |

Чтобы перенести программу на другой диск или компьютер, закройте её и перенесите **всю папку**, включая `Data`, DLL, `locales` и `resources`. Пробелы и кириллица в пути допустимы. Папку можно переименовать. EXE отдельно от остальных файлов работать не будет.

«Сохранить как» и экспорт позволяют выбирать внешние папки. Эти файлы не перемещаются вместе с приложением: их нужно перенести отдельно. Текущие внешние проекты из прежней рабочей версии можно открыть через «Файл → Открыть», затем сохранить в `Data/Projects` новой сборки. Старые пользовательские папки не удаляются и автоматически в публичный архив не попадают.

Для обновления распакуйте новую версию в отдельную папку, закройте обе версии и перенесите туда свою `Data`. Не заменяйте папку с пользовательскими данными чистым архивом. Не запускайте изнутри ZIP или из папки без права записи. Сборка не имеет отдельной подписи издателя AlertStudio; Windows может показать предупреждение при скачивании. Поддержка macOS, Linux, Windows ARM и свежая физическая Windows-машина этой проверкой не подтверждены.

## Состав готового архива

Упаковщик копирует явный список файлов установленного Electron x64, локализации, скомпилированные main/preload/UI, минимальный `resources/app/package.json`, инструкции, лицензии и SHA-256-инвентарь. Production-зависимости включены в JavaScript-бандлы. `resources/default_app.asar` не нужен и исключён. Пакеты-примеры расширений устанавливаются отдельно.

Не включаются исходники, node_modules, тесты, скриншоты, референсы, PDF сравнения, документация разработки, временные файлы, логи, карты исходников, Data, проекты и их резервные копии. Аннотированные Git-метки прежних версий остаются в репозитории и в рабочий архив не входят. Это сохраняет прежние контрольные версии, не раздавая пользовательские бэкапы.

`distribution-manifest.json` позволяет проверить комплектность и хеши файлов. Файл `*.zip.sha256` содержит контрольную сумму ZIP. Эти хеши проверяют целостность и не заменяют подпись издателя.

## Проверяемый выпуск

Из папки AlertStudio на Windows x64:

```powershell
pnpm install --frozen-lockfile
pnpm check
pnpm test:ui
pnpm package:portable
pnpm test:portable
```

Результат: `release/AlertStudio-<версия>-Windows-x64/`, одноимённый ZIP и файл SHA-256. Рабочая `Launch.exe` остаётся средством запуска разработки с зависимостями; готовый `AlertStudio.exe` содержит собственный движок.

Повторная упаковка заменяет только неизменённую чистую сборку с проверенным инвентарём. Если в ней появились Data или изменённые файлы, упаковщик останавливается: сначала перенесите использованную папку в другое место. Он не удаляет пользовательские данные ради пересборки.

`test:portable` распаковывает фактический ZIP в собственную тестовую папку. Запускает настоящий EXE из посторонней текущей папки с PATH только Windows/System32 и заблокированным разрешением сетевых имён. Проверяет Save, многофайловый проект, PNG и отдельное окно; создаёт черновик и устанавливает тестовое расширение. Затем копирует всю тестовую папку на **другой диск**, делает исходный путь недоступным и проверяет сохранность профиля/раскладки, открытие проекта, восстановление и расширение. По умолчанию используется E:; другой доступный диск задаётся `ALERT_STUDIO_TEST_DRIVE`. Удаляется только собственная проверенная временная папка на этом диске. Результат — `artifacts/portable-results.json`. Контроллер теста использует среду разработчика; сама запущенная программа — только файлы из архива. Это не проверка на отдельном физическом компьютере.

После успешных проверок сохраните исходники, README и release notes в коммите. Создайте аннотированную `v<версия>` и уникальную `backup/дата-описание`, соблюдая [правило контрольных версий](backups.md). До обновления main сохраните её предыдущую удалённую вершину, если backup-метки для неё ещё нет. Отправьте main и **явно названные новые метки** атомарно и проверьте удалённые SHA.

Затем выполните `node tools/github-release.mjs`. Скрипт проверяет чистоту исходников, удалённые branch/version/backup refs, готовую папку, SHA архива и успешный отчёт portable-теста для этого же архива. Создаёт draft, загружает ZIP и SHA, проверяет размеры/хеши и только затем публикует Release. Существующие выпуски не перезаписываются. Для проверки доступа без публикации: `node tools/github-release.mjs --inspect`. Используются Git Credential Manager либо GH_TOKEN/GITHUB_TOKEN; секреты не записываются в проект и не выводятся.

В итоговом сообщении пользователю нужны ссылка на Release и готовый ZIP, опубликованный коммит, контрольная метка и результаты проверок. Ветку с исходниками и backup-метку нельзя выдавать за скачиваемую готовую программу.
