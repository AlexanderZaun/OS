# Папка проекта v1 (экспериментальная)

project.json содержит только id/name/format/revision/scene. Данные лежат в `revisions/<uuid>/scenes/main/`: scene.json содержит ID объектов; `settings/width.json`, height.json, background.json — независимые значения сцены. `objects/<id>/object.json` содержит metadata и settingIds; `objects/<id>/settings/<key>.json` — значение. `revisions/<uuid>/modules.lock.json` записывает точные версии эффектов и SDK. Ссылки типов объектов должны присутствовать в lock. Версия пакета, несовпадающая с lock, не используется до явной миграции; сохранение неизвестных данных остаётся доступным.

Ревизии неизменяемы. Save сначала создаёт целое новое дерево, затем меняет единственный project.json через rename временного индекса. Это не атомарная последовательность rename множества файлов: опубликован только один указатель, старое дерево остаётся пригодным. Прерывание до переключения оставляет старый проект, незавершённые неиспользуемые ревизии инертны. Fault injection тест проверяет это. Файлы проверяются по типам, ID, относительным ссылкам и соответствию ID metadata.

Каждый JSON перед публикацией закрывается после FileHandle.sync(). Перед переключением индекса `project.previous.json` получает указатель на полностью проверенную предыдущую ревизию. При первом сохранении резервный индекс ссылается на полностью записанное первое дерево. При повреждении/отсутствии основного индекса read открывает и проверяет резервное дерево; usedBackup явно отображается в UI, документ становится dirty. Повторное сохранение не копирует повреждённые байты поверх хорошей резервной копии. Проверены сбои после metadata, после backup и до commit, включая отсутствующий primary. Сохранение в папку с другим project ID отклоняется.

В Windows `FolderLease` удерживает эксклюзивный локальный named pipe по хешу канонического пути папки на весь период редактирования. Другой сотрудничающий процесс на этой машине получает projectBusy; ОС освобождает handle при аварии. Не используются TCP/OBS server или автоматически удаляемый stale lock-файл. Альтернативные ОС и координация разных машин на сетевой папке не поддержаны/не проверены.

Автосохранение: `userData/Recovery/<project-id>/` имеет отдельное многофайловое дерево и recovery.json с name/time/origin/active. Debounce 700 ms; запись сериализована, изменения во время записи попадают в следующий снимок. UI сообщает pending/saving/saved/error. Восстановление открывает несохранённую копию и не пишет origin. Явное Save деактивирует предложение восстановления; «Скрыть» также только деактивирует metadata, не удаляя данные. При обычном выходе очередь дописывается до app.quit. Ошибка последней записи не скрывается: можно вернуться в приложение или явно выйти без нового черновика.

Это проверенное восстановление после ошибки процесса, не абсолютная гарантия при физическом отключении питания: долговечность directory entries/rename и поведение конкретного накопителя не проверялись. Старые ревизии не удаляются автоматически. Retention/сбор мусора, экспорт переносимого архива, assets и stage tracks ещё впереди.

Неизвестные эффекты сохраняются и отмечаются в Properties; на холсте отсутствующий effect пока не рисует видимую рамку-заглушку. Открытие папки читает только данные, пакетный код из проекта не выполняется.
