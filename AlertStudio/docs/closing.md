# Закрытие приложения и несохранённые изменения

Обновление 17.10.2026. При закрытии главного окна с изменённым проектом появляется диалог общей темы приложения с RU/EN, именем проекта и папкой сохранения. Закрытие главного окна завершает все окна. Закрытие отдельной панели закрывает только её.

| Выбор | Поведение |
|---|---|
| Сохранить и закрыть | Сохраняет текущую модель в папку проекта, дожидается завершения записи и очистки кандидата восстановления, затем закрывает приложение. Для нового/восстановленного проекта сначала выбирается папка. |
| Закрыть без сохранения | Сохранённая ревизия проекта остаётся прежней. Отложенная новая запись черновика отменяется; уже начатая завершается, затем текущий кандидат восстановления деактивируется. Приложение закрывается. |
| Отмена | Окна, текущие правки и действующий черновик остаются открытыми. Enter по умолчанию выбирает отмену; Escape также отменяет закрытие. |

Отмена выбора папки возвращает к диалогу с пояснением. Ошибка сохранения или завершения закрытия показывается там же; приложение остаётся открытым. Можно повторить сохранение, выбрать закрытие без сохранения или вернуться к редактированию. Во время записи кнопки закрытия и Escape заблокированы; фокус остаётся внутри диалога.

Если проект не изменён, подтверждение не требуется. Если закрытие запрошено во время выбора папки/записи/открытия проекта, запрос ожидает окончания этой операции и затем проверяет актуальное состояние. Сохранение и закрытие не выполняются параллельно с другой операцией проекта.

## Отдельные окна и защита от гонок

Диалог показывается только в одном окне. Другие окна получают уведомление и блокируют изменение модели. Main проверяет владельца диалога, request ID и допустимую фазу ответа; повторные запросы закрытия не создают второй диалог. Изменение проекта через IPC во время подтверждения также отклоняется. Завершение через app.quit проходит тот же сценарий.

CloseCoordinator находится в app/bootstrap/close-coordinator.ts, состояния и выборы — contracts/close.ts. У него нет зависимостей от Electron или React. Main отвечает за оконный жизненный цикл; Shell использует ui-kit/Dialog.tsx. Dialog теперь поддерживает closeDisabled и удерживает фокус, когда все кнопки временно отключены.

ProjectSession.dispose(true) отменяет timer, ждёт очередь черновика, деактивирует только текущий кандидат и освобождает lease после успешного завершения. При ошибке правки и lease сохраняются, запись черновика возобновляется. Другие кандидаты не скрываются. Деактивация не удаляет физические файлы старых ревизий Recovery и не является функцией очистки диска.

Автовосстановление после аварии сохраняется. Принудительное завершение процесса, app.exit и отключение питания не проходят обычный диалог; последние ещё не записанные правки по-прежнему зависят от интервала автосохранения и состояния диска. Отдельный native fallback для сломанного renderer ещё не реализован.

## Проверки

34 логических теста, включая шесть новых: Cancel, отмена папки, ошибка Save/retry, сериализация ответов и ожидание завершения, ошибка discard/retry, clean close, ожидание in-flight draft, сохранность явного проекта/других кандидатов и удержание lease при ошибке.

Все девять Electron scripts прошли единым финальным прогоном. tests/close-smoke.mjs проверяет настоящий window close/app.quit, все кнопки, RU/EN, Enter/Escape/focus trap, очередь закрытия во время folder picker, owner/IPC guards, сохранение последних значений, discard сохранённого и нового проекта и повторный запуск. Выбор папки/ошибочный путь подменены тестом; запись и открытие проектов настоящие. Recovery smoke сохраняет crash recovery и теперь проверяет явное «Сохранить и закрыть» при обычном выходе.

Снимки просмотрены в 1920×1080 и 900×650. Артефакты: artifacts/close-ui-results.json, artifacts/screenshots/close-1080.png и close-compact.png. Helper resizeWindow теперь выбирает BrowserWindow по конкретной Page, а не по порядку окон Electron.

## Возможные следующие доработки

* Отдельный осознанный выбор «Закрыть с черновиком» для продолжения работы позже без выбора папки; он должен отличаться от «без сохранения».
* Краткое описание несохранённых изменений и переход к последней явно сохранённой версии.
* Резервный native диалог для аварии renderer и понятная процедура выхода при недоступном диске.

Эти дополнительные пункты пока не реализованы; текущий диалог содержит только два действия закрытия и отмену.
