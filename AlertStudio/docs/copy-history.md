# Копирование параметров и история действий

## Копирование

В меню «Объект» находятся «Копировать параметры» и «Вставить параметры…». Те же кнопки доступны среди инструментов ⌕ в свойствах объекта. Copy сохраняет снимок известных значений эффекта и оформления слоя во внутренний буфер приложения; это не системный буфер Windows. Снимок общий для всех окон и не меняется вслед за последующими правками/удалением донора. Копировать можно и из заблокированного слоя. Копирование не меняет проект, dirty, историю или состояние явного сохранения.

Вставка открывает общий Dialog с именем донора и выбором областей:

- Параметры эффекта доступны только при совпадении типа и точной версии установленного эффекта. Переносятся известные параметры, включая скрытые; неизвестные ключи получателя сохраняются.
- Связи с источниками и управляющие их режимы по умолчанию исключены. Отдельная галочка включает их перенос. Все ссылки проходят обычные проверки существования/типа/self/cycle. Если хотя бы одна неверна, отклоняется вся вставка, включая оформление, а не только проблемное поле.
- Координаты по умолчанию исключены. Они определяются из editor.position для текущего/копируемого режима; без editor metadata используется fallback x/y. Переключение режима связи может менять систему координат и фактическое положение композиции даже при сохранённых числах.
- Оформление слоя включается отдельно. Оно совместимо между разными типами объектов и не требует доступного эффекта. Если донор не имел оформления, это означает обычные базовые значения, а не сохранение стиля получателя.

Имя, UUID, видимость, блокировка, Solo и метка получателя не копируются. Заблокированный получатель защищён в UI и core. Весь paste — один undo. Пустая/неизменяющая вставка не создаёт новую запись истории. Диалог закрывается при смене ревизии/выделения/блокировке или общей операции проекта; команда также проверяет ожидаемую revision. Отмена ничего не меняет. Открытие/создание проекта и восстановление черновика очищают буфер; перенос между проектами/сеансами и текстовый импорт/экспорт буфера не реализованы.

## История

«Правка → История действий» открывает необязательную перемещаемую панель. Она также доступна через команды меню «Окно», включая дополнительное представление и отдельное окно. При первом открытии история добавляется вкладкой рядом со свойствами, чтобы не дробить маленький экран на дополнительные полосы. Панель можно перенести обычным способом; её состояние общее для всех представлений.

В списке видны название действия, имя объекта/параметра, время и состояния «Применено», «Отменено», «Текущее состояние». Свежие действия сверху. Нажатие строки возвращает проект к состоянию **после** выбранного действия. Можно перейти к отменённому действию, восстановив промежуточные правки, либо к началу доступной истории. Шагов максимум100, как и прежний предел undo: после отсечения старых шагов начало означает самое раннее ещё доступное состояние, не обязательно пустую сцену.

Undo/redo в панели, меню, клавиатуре и других окнах используют одну историю. Переход по нескольким шагам проверяет revision и публикует один итоговый снимок; он не исполняет проектный код или записанные команды заново. Новая правка после undo удаляет ветку redo. No-op, ошибочные команды, копирование, выделение, поиск, камера, playback и экспорт не создают шагов. Изменения стадий уведомления создают шаги, поскольку это значения проекта. Блокировка не запрещает undo/redo.

История и буфер существуют только в памяти текущего сеанса. Явное Save сохраняет текущие значения и не очищает историю; Open/New/Recovery начинают её заново. На диске остаётся прежний многофайловый проект, без команд, истории или буфера. GitHub backup tags и резервные файловые ревизии — отдельные механизмы, эта панель ими не управляет.

Контракты: optional Snapshot.clipboard/history для совместимости старых панелей; commands settings-copy, settings-paste (keys/appearance/revision), history-jump (target/revision). В main хранится единственная авторитетная копия; UI не передаёт произвольные вставляемые значения. Session.changed сравнивает именно project, поэтому копирование не инициирует autosave новой правки.
